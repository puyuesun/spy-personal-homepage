## 1. 本版本做了什么

三件事，都在**首屏 Hero**：

1. **漂浮 3D 粒子动态背景**：把首屏背景换成 Magic UI 的 **Floating 3D Particles** 效果——
   深色背景上漂浮着持续旋转、缓缓上浮的 3D 粒子星场，粒子近大远小、有纵深层次，
   在首屏边缘柔和淡出，与克莱因蓝主色调一致。
2. **「联系我」按钮改用 Shimmer Button**：把 Magic UI 的 **Shimmer Button** 效果做进首屏主按钮——
   按钮边框一圈白光持续扫过（沿边缘流动），带内部高光与轻微上浮交互，仍是原来的克莱因蓝主色按钮。
3. **鼠标指针交互（本版本独有）**：鼠标在首屏移动时，**指针附近的粒子会被缓慢推开**，
   像拨开一层浮尘；指针移开后粒子再缓慢合拢回原位。两个方向都是平滑渐变的，
   没有一下弹开、也没有回弹余震。

三项均为**原生移植**（第 3 项为在原有效果上的自有扩展），页面依旧零依赖、可直接双击打开。

## 2. 关于「官方 CLI」与落地方式的说明（重要）

你提供的命令是官方安装方式：

```bash
pnpm dlx shadcn@latest add @magicui/floating-3d-particles
```

**实际情况**：该命令面向 **React + Tailwind + shadcn/ui** 工程，执行后会在项目中生成
`components/ui/floating-3d-particles.tsx`（React 组件文件）。而本项目是**纯静态 HTML/CSS/JS**，
没有 React 工程与构建流程，直接执行 CLI 无法产出可被本页面引用的文件。

因此本版本采用**原生等价移植**：

| 项目 | 说明 |
|---|---|
| 官方实现 | React 外壳 + **Canvas 2D 伪 3D**（并非 Three.js） |
| 官方源码 | `registry/magicui/floating-3d-particles.tsx` |
| 获取方式 | 从官方 registry 直接取回源码：`https://magicui.design/r/floating-3d-particles.json` |
| 本版本做法 | 按官方源码**逐段等价改写为原生 JavaScript**，算法与参数体系完全一致，零依赖 |

Shimmer Button 同理，官方源码取自 `https://magicui.design/r/shimmer-button.json`
（`registry/magicui/shimmer-button.tsx`），本版本改写为一份原生 CSS。

> 也就是说：**视觉效果与官方组件一致，且不需要引入 Node/React 工程**，页面仍是可直接双击打开的静态文件。

## 3.5 Shimmer Button 参数（首屏「联系我」按钮）

官方是 React 组件 + Tailwind 的 `animate-shimmer-slide` / `animate-spin-around` 两段动画，
本版本用一份 CSS 等价实现（`style.V2.1.css` 中的 `.btn-shimmer` 段），不需要 Tailwind 与构建流程。

| 参数（CSS 变量） | 本版本取值 | 官方默认 | 说明 |
|---|---|---|---|
| `--shimmer-color` | `#ffffff` | `#ffffff` | 扫光颜色 |
| `--spread` | `90deg` | `90deg` | 光带张角 |
| `--speed` | `3s` | `3s` | 扫光一轮周期（自旋为其 2 倍 = 6s） |
| `--cut` | `0.1em` | `0.05em` | 边缘光带可见宽度；本版本略放大，便于在深色窄按钮上看清 |
| `--radius` | `12px` | `100px` | 圆角；官方默认胶囊形，这里与页面其它按钮统一为 12px |
| `--bg` | 克莱因蓝渐变 `#002fa7 → #2f6bff` | `rgba(0,0,0,1)` | 按钮底色 |

**层级结构**（与官方组件一一对应）：

| 层 | 类名 | 作用 |
|---|---|---|
| 1 | `.shimmer-spark` | 光带容器：`z-index:-30` + `blur(2px)` + `container-type:size`（给 cqw/cqh 提供参照） |
| 2 | `.shimmer-spark-slide` | 水平滑动层（`shimmer-slide` 动画） |
| 3 | `.shimmer-spark-beam` | `conic-gradient` 光带 + 自旋（`spin-around` 动画） |
| 4 | `.btn-label` | 按钮文字 |
| 5 | `.shimmer-highlight` | 内阴影高光（hover / active 时增强） |
| 6 | `.shimmer-backdrop` | 内缩 `--cut` 的遮罩：`z-index:-20`，只露出边缘一圈光带 |

> 关键点：按钮自身设 `position: relative; z-index: 0` 以建立层叠上下文，
> 否则负 `z-index` 的光带层会被页面背景盖住，扫光就看不见了。
> 想调观感只改 `.btn-shimmer` 顶部那几个 CSS 变量即可；想恢复官方胶囊形，把 `--radius` 改成 `100px`。
> 另外已按无障碍要求处理：`prefers-reduced-motion: reduce` 时两段动画都停用。

## 3.6 鼠标指针交互参数（首屏粒子，本版本独有）

官方 Floating 3D Particles **没有**指针交互，这一项是在移植基础上自行追加的，
参数位于 `script.V2.1.js` 的 `CONFIG.interact`：

| 参数 | 取值 | 说明 |
|---|---|---|
| `enabled` | `true` | 交互总开关 |
| `radius` | `190` | 影响半径（px）：指针进入这个范围才推开粒子 |
| `displace` | `46` | 指针正中心处的最大推开距离（px），决定"散开多少" |
| `ease` | `0.035` | 缓动系数 0–1，越小越慢越柔（时间常数 ≈ 0.48 秒） |

**实现方式：目标偏移 + 指数缓动（不是弹簧）**

每个粒子只保存一个「偏移量」（`offX/offY`），逐帧做两步：

1. **算目标**：粒子基准位置到指针距离 `d < radius` 时，
   目标偏移 = 沿「指针 → 粒子」方向 × `displace × (1 - d/radius)²`；
   `d ≥ radius` 时目标为 0（也就是回归原位）
2. **缓动逼近**：`偏移 += (目标 - 偏移) × ease`，逐帧朝目标靠拢

之所以用缓动而不是弹簧-阻尼积分：缓动公式里**没有速度项**，
偏移永远只朝目标单调逼近、不会越过目标，因此**从原理上不可能出现回弹或震荡**。
早先的弹簧版本虽然"弹回"更有物理感，但阻尼偏小（阻尼比 ≈ 0.15，属于欠阻尼），
回位时会来回摆动，观感偏"跳"，所以按需求改成了缓动模型。

现在两个方向都是平滑的：指针靠近 → 粒子**缓慢散开**；指针移开 → 粒子**缓慢合拢回原位**，
没有一下弹开、也没有回弹余震。实测散开过程（每 0.35 秒的 max 偏移）
`22.5 → 28.1 → 31 → 34.8 px`，增量逐段收敛；归位过程（每 0.4 秒）
`14.8 → 6.3 → 2.7 → 1.1 → 0.5 px`，单调递减、无回升。

**其他细节**：

- 事件绑在 `.hero` 上而非画布上——粒子层是 `pointer-events: none`，
  鼠标事件会穿透到 hero，因此**鼠标移到标题、按钮上时同样能推开粒子**
- 指针坐标用 `clientX/Y` 减去画布 `getBoundingClientRect()`，与引擎共用同一套 CSS 像素坐标系
- 计算距离时用粒子的**基准位置**、不含它自己已有的偏移；
  否则"被推开 → 距离变大 → 目标变小 → 又凑近"会自激成原地抖动
- 粒子恰好落在指针正中心时方向未定义：用粒子自身的极角给一个**稳定**方向，
  刻意不用随机方向（每帧换向会导致原地抖动）
- 页面滚动时会用缓存的指针位置重算坐标，避免斥力作用点相对画布漂移
- 粒子越过上下边界重生时同步重置偏移，避免新位置的粒子带着旧偏移出现
- 目标已归零且偏移降到 0.1px 以下时直接置 0，不留肉眼看不见的残差
- `prefers-reduced-motion: reduce` 时交互停用，并清空已有偏移

**调参速查**：散开幅度不合适 → 改 `displace`；散开/归位节奏不合适 → 改 `ease`（越小越慢）。

## 4. 算法链路（与官方一致）

1. **布点**：以极坐标随机撒点（随机角度 + 随机半径 + 随机纵向位置）
2. **透视投影**：由 `depth` 推导 `fov`（800→200）、`perspectiveDistance`（100→800）、`depthRange`，
   逐帧计算缩放系数 `scale = fov / (fov + pd + sin(angle) × depthRange)`
3. **运动**：每帧角度持续增加（绕中心轴旋转）+ 纵向匀速上浮
4. **重生**：粒子越过上/下边界后从**对侧**重新进入，并重新随机半径，保证粒子场不枯竭
5. **绘制**：按 `projectedScale` 排序，**由远及近**绘制（画家算法），保证遮挡关系正确

**无障碍与性能**（沿用官方设计）：

- `prefers-reduced-motion: reduce` → 只绘制一帧静态画面，不逐帧旋转
- `IntersectionObserver`：首屏滚出视口后自动暂停动画（省电）
- `visibilitychange`：切到后台标签页自动暂停
- `ResizeObserver`：容器尺寸变化时重建画布与粒子
- 设备像素比（DPR）上限 2，避免高 DPI 屏上过度渲染

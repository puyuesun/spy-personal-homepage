# 个人主页建设方案（Vibe Coding 课程 · 大一学生版）

> 目标：按课程「V1 → V2 → V3 → V4 + 期末扩展」的要求，做一个**能发布、能收反馈、能持续改进**的个人主页。
> 本文件只做方案规划，**暂不制作网页**。方案追求「真实可行」——每一步都能在无编程基础的情况下用 AI 辅助完成。

---

## 〇、已确认决策（2026-09 与本人确认）

| 项目 | 决定 |
|---|---|
| 技术栈 | 原生 HTML/CSS/JS + **GitHub Pages** 发布 + **Supabase** 收反馈（采纳推荐方案） |
| 视觉风格 | **简约科技感**（深色为主、克制留白、轻微光效/渐变） |
| 语言 | **中英双语** |
| 主题 | 自带**深色/浅色模式切换**，默认深色 |
| 账号现状 | GitHub、Supabase **均未注册** → 需从零注册与配置（见第八节） |
| 个人资料 | **稍后提供**，先以结构方案推进 |

---

## 一、定位与目标（先想清楚，再动手）

在动手前必须先回答三个问题，这套答案将决定页面结构：

| 问题 | 建议答案（可按你真实情况调整） |
|---|---|
| **服务谁（受众）** | 未来可能的 HR / 导师、同学、竞赛队友、想了解你的人 |
| **展示什么（核心信息）** | 我是谁、我在学什么、我做过什么、我的技能与兴趣、如何联系我 |
| **希望访问者做什么（目标动作）** | ① 留下反馈　② 通过邮箱/GitHub 联系我　③ 查看我的项目 |

**成功标准（自检）**：一个陌生人 30 秒内能说清楚「你是谁、做过什么、下一步能做什么」。

---

## 二、推荐技术方案（新手最省力、最可交付）

| 层级 | 推荐方案 | 理由 |
|---|---|---|
| 页面 | 单个 `index.html` + `style.css` + 少量 `script.js`（原生三件套） | 无需构建工具，双击即可本地预览，AI 生成最稳定 |
| 样式 | 手写 CSS 或 Tailwind CDN | 不装环境，直接改；容易让 AI「小步修改」 |
| 代码托管 | **GitHub** 仓库 | 课程阶段二要求 Git checkpoint；也是发布基础 |
| 公开发布 | **GitHub Pages** | 免费、有公开链接、与 GitHub 仓库天然集成 |
| 反馈后端 | **Supabase**（Postgres + 自动 REST API） | 大纲明确点名；提供 Dashboard 直接查看提交 |
| AI 工具 | DeepSeek / ChatGPT / Claude 等任选 | 课程允许自选，重点是你能检查和解释 |
| 本地预览 | 浏览器直接打开，或 VS Code + Live Server | 满足「本地可预览」 |

> 备选：部署用 Vercel / Netlify（也能给公开链接）；反馈后端也可用 Supabase 之外的方案，但**建议严格按大纲用 Supabase**，避免踩坑、也符合课堂说明。

---

## 三、页面结构（单页 + 锚点导航）

```
顶部导航栏（固定）
├── 首屏 Hero       ：姓名 + 一句话定位 + 头像 + 主按钮（看项目 / 联系我）
├── 关于我 About    ：一段真实自述（专业、年级、方向、正在学什么）
├── 技能 Skills     ：工具/语言/课程，用标签或进度条展示
├── 项目/经历 Projects：卡片列表（课程项目、比赛、社团、实践）
├── 兴趣/其他（可选） ：让你更立体
├── 反馈 Feedback    ：表单（V3 加入）
├── 联系方式 Contact ：邮箱、GitHub 等
└── 页脚 Footer      ：版权、更新时间、开源许可说明
```

## 四、功能清单（按阶段递进）

### V1｜能看 + 本地预览（阶段一）
**目标：先把想法变成可观察的产品。**

必备功能：
- [ ] 首屏展示：姓名、一句话自我定位、头像、1–2 个行动按钮
- [ ] 关于我：真实简介（专业、年级、方向、目标）
- [ ] 项目/经历：至少 2–3 条真实条目（课程项目、比赛、社团、志愿等）
- [ ] 联系方式：邮箱（可加 GitHub）
- [ ] 响应式：手机上也能正常看
- [ ] 本地预览：浏览器双击可打开
- [ ] 保存 V1 副本 + 记录下一轮改进点

> 验收：内容真实可核验、结构清楚、主要入口可用。

---

### V2｜打磨出「像自己的作品」（阶段二）
**目标：把模糊审美变成可执行修改，一次只改一类问题。**

建议功能（从中挑重点，不必全做）：
- [ ] 统一配色方案（主色 + 辅助色 + 中性色）与字体层级
- [ ] 顶部锚点导航 + 平滑滚动 + 当前区块高亮
- [ ] 卡片/按钮的悬停、过渡等微交互
- [ ] **深色/浅色模式切换（已确认要做，默认深色）**
- [ ] **中英文切换（已确认要做）**
- [ ] **简约科技感视觉**：深色底 + 单一主色点缀 + 细边框/微光效 + 充足留白
- [ ] 项目卡片支持链接（GitHub / Demo / 截图）
- [ ] 头像与图片优化（压缩、懒加载）
- [ ] 可选：一键下载简历 PDF（放一个 `resume.pdf` 链接）

版本要求：
- [ ] 完成多轮**有明确目的**的修改（如：第 1 轮排版、第 2 轮配色、第 3 轮动效）
- [ ] 保存 V1 与 V2，用一两句话说明每轮变化
- [ ] 保留前后对比截图

---

### V3｜加入 Feedback + 公开发布（阶段三）
**目标：让真实访问者可以使用并回应。**

功能：
- [ ] **反馈表单**：字段建议（保持简单）
  - 昵称/称呼（选填）
  - 身份类型（选填：同学 / 老师 / HR / 亲友 / 其他）
  - 反馈内容（必填，文本框）
  - 评分或「最有帮助的一点」（选填）
- [ ] 提交校验（非空、长度限制）+ 防重复提交
- [ ] 提交成功/失败的清晰提示（Toast 或文字）
- [ ] 数据写入 Supabase，可在 Dashboard 查看
- [ ] 发布到 GitHub Pages，获得公开链接
- [ ] 从公开链接重测：页面、表单、反馈全流程

课后任务：
- [ ] 邀请 ≥3 位不同类型的人访问
- [ ] 收集 3–5 条有意义的反馈（内容 / 结构 / 体验 / 新需求）

**数据流（要能讲清楚）：**
```
浏览器页面 → HTTPS 请求(anon key) → Supabase REST API → Postgres 表(feedback)
                                        ↑ 行级安全策略 RLS 限制可写不可读
你在 Supabase Dashboard → Table Editor 查看所有提交
```

---

### V4｜反馈驱动的第一月版本（阶段四）
**目标：把反馈转化为产品决定。**

功能/产出：
- [ ] 反馈分类表：事实问题 / 个人偏好 / 新需求
- [ ] 对每条反馈做决定：采纳 / 部分采纳 / 暂缓 / 不采纳 + 理由
- [ ] 落实优先级最高的改进（通常 ≤5 项，务求做透）
- [ ] 回归测试：确认改动没破坏原功能和反馈流程
- [ ] 复盘文档：用户说了什么 → 你改了什么 → 下一步做什么

提交物：
- [ ] V4 公开链接
- [ ] V1→V4 版本链与变化说明
- [ ] 反馈证据（≥3 人、3–5 条，截图/记录）
- [ ] 改进说明与验证结果

---

### 期末扩展（5%）｜选一个方向做深
建议从以下三个方向中**选一个**：

1. **Digital Twin（推荐）**
   - 采集你自己的资料（简历、项目、FAQ）建立小型知识库
   - 在主页加一个「问问我」聊天框，回答与「你」相关的问题
   - 实现路径：前端对话 UI → 调用大模型 API（或用 Supabase Edge Function 代理，避免暴露密钥）→ 用知识库内容作为上下文
2. **项目库**：把本学期所有项目结构化展示（分类、技术栈、链接、复盘）
3. **一个主要新功能**：如博客/学习日志、时间线、成就系统等

> 注意：仅改颜色、字体或少量文字不算主要扩展。

---

### 独立小作业（5%）
- 做一个**不是个人主页**的网站或小程序
- 建议主题：课程表工具、读书打卡、校园二手、心情日记、小游戏等
- 复用同一套方法：V1 → 打磨 → 发布 → 反馈 → 改进
- 交付：可访问版本 + 简短迭代说明

## 六、安全、隐私与学术诚信（红线）

- [ ] **绝不**在 HTML/JS/公开仓库中放 Supabase `service_role` 密钥（前端只能用 `anon` key）
- [ ] 为反馈表开启 **RLS**：允许匿名 `INSERT`，禁止匿名 `SELECT`
- [ ] 不收集身份证号、电话、住址等敏感信息
- [ ] 头像、照片、经历等**真实**，不虚构
- [ ] 参考他人设计时遵守开源许可，保留来源说明
- [ ] 不伪造反馈或截图，不冒用他人身份

## 八、从零开始：GitHub 与 Supabase 注册配置指引

> 你目前两个账号都没有，按下面顺序做即可。全部免费。

### 8.1 GitHub（阶段二保存版本、阶段三公开发布需要）
1. 打开 `https://github.com` 注册账号。用户名建议**英文、简洁、专业**（如 `zhangsan-ai`），它会出现在主页链接里。
2. 到邮箱完成验证。
3. 新建一个仓库（Repository），例如命名 `personal-homepage`；发布后链接形如 `https://<用户名>.github.io/personal-homepage/`。
4. 开启发布：仓库 **Settings → Pages → Source = Deploy from a branch → main / (root)**，保存后等 1–2 分钟。
5. 上传代码两种方式：
   - **图形界面（新手友好）**：网页版仓库直接 `Add file → Upload files` 把 `index.html` 等传上去。
   - **Git（更规范，能练 checkpoint）**：安装 Git，配置 `git config user.name/user.email`，`git add / commit / push`。
6. 以后每次版本更新，重复「提交 → 等待 Pages 重新构建」，并把提交信息写成版本说明（如 `v2: 统一配色与导航`）。

### 8.2 Supabase（阶段三反馈后端需要）
1. 打开 `https://supabase.com` 注册（可直接用 GitHub 登录）。
2. 新建项目 **New project**：设置名称、数据库密码，Region 建议选 **Singapore**（离国内较近，速度更好）。
3. 建反馈表：进入 **SQL Editor**，执行：

```sql
create table public.feedback (
  id          bigint generated by default as identity primary key,
  name        text,
  role        text,          -- 身份类型：同学 / 老师 / HR / 亲友 / 其他
  message     text not null, -- 反馈内容
  score       int,           -- 可选评分
  created_at  timestamptz default now()
);

-- 开启行级安全
alter table public.feedback enable row level security;

-- 允许匿名“提交”，但禁止匿名“读取”
create policy "anon can insert feedback"
  on public.feedback for insert
  to anon
  with check (true);
```

4. 在 **Project Settings → API** 复制两个值：
   - `Project URL`
   - `anon public` key（**可以**放进前端代码）
   - `service_role` key（**绝对不能**放进前端或公开仓库）
5. 前端提交流程：HTML 表单 → `fetch()` 向 `Project URL/rest/v1/feedback` 发送 `POST`，请求头带 `apikey: <anon key>`，请求体为 `{ name, role, message, score }`。
6. 查看反馈：Supabase 左侧 **Table Editor → feedback**，或 Dashboard 里的查询界面。

### 8.3 安全红线（务必遵守）
- 前端只暴露 `anon` key；`service_role` 一旦泄露等于把整个数据库交出去。
- 必须开启 **RLS**：允许匿名 `INSERT`，禁止匿名 `SELECT`，否则任何人都能读走全部反馈。
- 不在反馈里收集身份证号、电话、住址等敏感信息。

### 8.4 建议的执行顺序
1. 先注册 GitHub（不着急配置发布，等 V1 做完再传）。
2. V1、V2 全部本地完成并保存版本。
3. V3 之前再注册 Supabase，建表、测试表单。
4. V3 完成后按 8.1 发布到 GitHub Pages，拿到公开链接。

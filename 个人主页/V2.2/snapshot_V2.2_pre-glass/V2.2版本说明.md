# V2.2 版本说明 — 孙璞月 Spy 个人主页

> **版本号**：V2.2
> **完成时间**：2026-09-14
> **基线版本**：V2.1
> **本版本主题**：**首屏以外的全部区域**新增 Magic UI **Interactive Grid Pattern（交互式网格背景）**——指针落在哪一格，哪一格就填充克莱因蓝高亮，移开后缓慢淡出；首屏保持 V2.1 原样不变
> **技术栈**：原生 HTML / CSS / JavaScript（零第三方依赖，可继续用 GitHub Pages 发布）

## 1. 本版本做了什么

一件事：**给首屏以外的所有区域铺上「会跟着鼠标亮起来的网格背景」**。

- 从「关于我」到页脚，整个页面背景是一张 56px 的网格
- **指针停在哪一格，那一格就被填充成克莱因蓝**
- 指针移开后，那一格**缓慢淡出**（约 1 秒），不是一下消失
- **首屏 Hero 完全没有变**：仍是 V2.1 的 3D 粒子星场 + 静态网格，指针在首屏内移动不会触发任何网格高亮
- 效果来源：Magic UI `Interactive Grid Pattern`，按官方源码**等价移植为原生 SVG + JS**，零依赖

三项要求全部满足：

| 要求 | 实现情况 |
|---|---|
| 用 Magic UI 的 Interactive Grid Pattern | ✅ 按官方源码等价移植（官方为 React + SVG） |
| 应用在**除了 hero 以外**的部分 | ✅ 网格层自 `--hero-h`（首屏高度）开始，一直到页面底部 |
| hero 不受影响 | ✅ 首屏仍是粒子 + 静态网格；实测指针在首屏内 0 格高亮 |

## 2. 关于「官方 CLI」与落地方式的说明（重要）

官方安装方式是：

```bash
pnpm dlx shadcn@latest add @magicui/interactive-grid-pattern
```

**实际情况**：该命令面向 **React + Tailwind + shadcn/ui** 工程，执行后生成
`components/ui/interactive-grid-pattern.tsx`（React 组件）。本项目是**纯静态 HTML/CSS/JS**，
没有 React 工程与构建流程，直接执行 CLI 无法产出可被本页面引用的文件。

因此沿用 V2.1 已确立的做法 —— **原生等价移植**：

| 项目 | 说明 |
|---|---|
| 官方实现 | React 组件 + 内联 SVG 网格 + Tailwind 工具类 |
| 官方源码 | `registry/magicui/interactive-grid-pattern.tsx` |
| 获取方式 | 从官方 registry 直接取回源码：`https://magicui.design/r/interactive-grid-pattern.json` |
| 本版本做法 | 按官方源码等价改写为原生 SVG + 原生 JavaScript，行为与参数体系一致，零依赖 |

> 官方文档页：https://magicui.design/docs/components/interactive-grid-pattern

### 2.1 官方原理解读

官方组件的核心是**三件事**：

1. **画网格**：一个 `<svg>` 里铺满 `width × height` 的 `<rect>` 方格
   （官方默认 `width=40, height=40, squares=[24,24]`，即 24×24 个 40px 方格）
2. **记录指针在哪一格**：React `useState` 保存 `hoveredSquare: [x, y]`，
   指针经过某个 `rect` 时把它的坐标写进 state
3. **高亮那一格 + 慢速淡出**：被选中的 `rect` 填充高亮色；官方用的是 Tailwind 类
   `transition-all duration-100 ease-in-out not-[&:hover]:duration-1000`
   —— **进入时 100ms 快速填充，离开时 1000ms 慢速淡出**

### 2.2 本项目的等价改写

| 官方做法 | 本版本做法 | 原因 |
|---|---|---|
| React `useState` 记录 hoveredSquare | 指针坐标反推格子索引 + 给对应 `<rect>` 切换 `.is-hover` 类 | 无 React |
| 固定 24×24 个 40px 方格 | 按容器尺寸动态计算行列数（26 列 × 57 行 = 1482 格），方格 56px | 需铺满整个页面区域，且要与首屏已有的 56px 网格对齐 |
| 在 `rect` 上用 `:hover` 触发 | 在 `window` 上监听 `pointermove`，用坐标换算定位 | **关键**：网格层是 `pointer-events: none`（避免挡住卡片点击与文字选择），此时 `rect` 收不到鼠标事件，官方的 `:hover` 方案在本页面**根本不会触发** |
| 高亮色 `gray-300/30` | 克莱因蓝 `rgba(47, 107, 255, 0.2)` + 描边提亮 + 两层辉光 | 贴合本页主色调；并按后续反馈调整过亮度（见 4.6） |
| 100ms 进入 / 1000ms 离开 | 完全一致（CSS `transition: fill, stroke, filter 1s` + `.is-hover` 时 `transition-duration: .1s`） | 保持官方手感，发光也一起快进慢出 |

> 也就是说：**交互手感与官方一致（快进慢出、指针所在格高亮），但因为是静态页面 + 网格层不拦截事件，必须改用坐标换算而不是 CSS `:hover`。**

## 4. 实现细节与踩坑记录

### 4.1 网格层只覆盖首屏以外

新增一个装饰层 `.igrid-layer`：

```css
.igrid-layer {
  position: absolute;
  left: 0; right: 0;
  top: var(--hero-h, 100vh);   /* ← 自首屏下沿开始 */
  bottom: 0;                   /* ← 一直到页面底部（含页脚） */
  z-index: -2;
  overflow: hidden;
  pointer-events: none;
}
```

`--hero-h` 由 `script.V2.2.js` 实测首屏高度后写入 `:root`（实测 907px），
并用 `ResizeObserver` 盯住 `.hero`，窗口尺寸变化时同步更新。

同时把**首屏原来的静态网格 `.bg-grid` 从「铺满整个视口」改为「只覆盖首屏」**
（`position: fixed; inset: 0` → `position: absolute; height: var(--hero-h)`）。
这样两套网格各管一段、互不重叠，首屏观感与 V2.1 完全一致。

> 注意：`body` 需要 `position: relative`，否则这两个绝对定位层会相对初始包含块定位而不是页面。

### 4.2 网格线与首屏对齐

首屏静态网格从页面顶部起按 56px 排布，而交互网格层是从 `hero 下沿` 开始算坐标的。
如果直接从 0 开始铺，两套网格线在交界处会**错开半个格子**。

处理：计算偏移量 `offsetY = 首屏高度 % 56`（实测 `907 % 56 = 11`），
让第一行方格上移 `offsetY`，于是两套网格的线条在交界处**严丝合缝**接上。
第一行被裁掉的上半截由 `.igrid-layer { overflow: hidden }` 吃掉。

### 4.3 为什么不用 CSS `:hover`

网格层必须 `pointer-events: none`（否则会挡住卡片上的按钮点击与文字选择），
而 `pointer-events: none` 的元素**收不到** `:hover`。
所以改为在 `window` 上监听 `pointermove`，用 `clientX/Y` 与网格层的位置反推格子索引。

### 4.4 性能处理

- **位置缓存**：网格层的 `getBoundingClientRect()` 只在生成网格、滚动、窗口变化时测量一次并缓存；
  指针移动时直接用缓存值算坐标，**不会触发强制重排**
- **只动两个节点**：切换高亮时只移除上一格的类、添加新一格的类，其余 1480 个 `rect` 不碰
- **不做逐帧重算**：浏览器本身已把 `pointermove` 按帧合并，无需再排队到 `requestAnimationFrame`

### 4.5 滚动后的高亮校正

页面滚动后网格层相对视口的位置变了，若指针不动，高亮会**停在旧格子上**。

处理：记录最近一次指针位置，滚动时刷新位置缓存并**用最近的指针坐标重新定位**
（而不是直接清掉高亮——直接清掉会出现「滚动事件晚于鼠标事件」时把刚点亮的一格误清掉的竞态）。

### 4.6 高亮的可见度增强与发光（V2.2 内微调，含一次亮度回调）

高亮效果在本版本内经过**两轮**调整，都是按反馈在同一版本内微调：

**第一轮 —— 让高亮更明显并带发光**

初版高亮沿用官方 `gray-300/30` 的量级（克莱因蓝 `0.18`）。实测在深色背景上偏含蓄，
因此做了增强：

| 手段 | 改动 |
|---|---|
| 填充调浓 | `rgba(47, 107, 255, 0.18)` → `rgba(47, 107, 255, 0.32)` |
| 描边提亮 | 高亮时描边由 `rgba(47, 107, 255, 0.05)` → 亮蓝，格子轮廓更清晰 |
| 加两层辉光 | `drop-shadow(0 0 6px …)` + `drop-shadow(0 0 16px …)` |
| 发光也参与过渡 | `transition` 的属性列表由 `fill` 扩展为 `fill, stroke, filter`，「快进 0.1s / 慢出 1s」的手感不变 |

**第二轮 —— 亮度调低（当前生效值）**

增强后实测格子内部平均亮度达 **98.70**（未高亮时仅 14.58），观感偏亮、偏刺眼，
因此按反馈把填充、描边、两层辉光的 alpha 一并收敛，**保留发光但整体压暗**：

| 手段 | 调整前 | **调整后（当前）** |
|---|---|---|
| 填充 | `rgba(47, 107, 255, 0.32)` | **`rgba(47, 107, 255, 0.2)`** |
| 描边 | `rgba(122, 176, 255, 0.85)` | **`rgba(110, 160, 245, 0.55)`** |
| 内层辉光（6px） | `rgba(110, 165, 255, 0.95)` | **`rgba(110, 165, 255, 0.55)`** |
| 外层辉光（16px） | `rgba(47, 107, 255, 0.6)` | **`rgba(47, 107, 255, 0.32)`** |

两层辉光的分工：**内层 6px** 紧贴格子形成亮晕（让格子看起来在「发光」），
**外层 16px** 向外扩散成柔和光斑（让光溢出格子边界，与周围环境产生关系）。

**实测效果对比**（同一格，指针移开并完全淡出后对比）：

| 指标 | 初版（无发光） | 第一轮（偏亮） | **第二轮（当前）** | 未高亮时 |
|---|---|---|---|---|
| 格子内部平均亮度 | 36.01 | 98.70 | **58.50** | 14.58 |
| 格子内部平均色 | — | RGB(44, 85, 168) | **RGB(25, 50, 100)** | RGB(6, 14, 24) |
| 格子**外圈**平均亮度 | — | 28.93 | **19.96** | 15.54 |

> 内部平均色 RGB(25, 50, 100) 说明高亮是**饱和的深蓝**，不是被辉光冲淡的灰蓝：
> 蓝通道约为红通道的 4 倍。
>
> 「外圈亮度」是发光的客观证据：格子外部本来没有填充，那圈区域变亮只可能来自辉光
> —— 当前外圈比未高亮时亮 **+4.42**，即**发光仍然存在，只是收敛得更含蓄**。
>
> 调法见 `.igrid rect.is-hover`：想让光更弱就调小两个 `drop-shadow` 的 alpha，
> 想让光更大就调大模糊半径（第一个值）。

### 4.7 无障碍

- 系统开启「减少动态效果」时，给 `<html>` 加 `.igrid-no-motion`，**取消填充过渡**，
  高亮改为瞬时切换（保留反馈，去掉动效）
- 整个网格层是 `aria-hidden="true"` 的纯装饰层，不进入无障碍树
- `pointer-events: none`，不影响键盘操作与文字选择

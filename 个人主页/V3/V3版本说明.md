## 1. 本版本做了什么

V3 在保留 V2.3 全部视觉与交互的基础上，新增一个完整的反馈闭环：

- 页面右下角新增固定悬浮按钮，桌面端约 100 × 100 px，移动端约 84 × 84 px。
- 按钮原生移植 Uiverse `fresh-goose-83`：环形 `FEEDBACK` 文字持续旋转，hover/focus 时中心箭头切换为“意见反馈”。
- 点击按钮后打开反馈弹窗。弹窗结构参考 `quiet-turkey-90`，背景参考 `brave-dog-61` 的深蓝三段渐变，输入区域参考 `curvy-earwig-22` 的多层渐变边框。
- 表单只收集必填反馈内容，长度 1–1000 字。
- 提交使用原生 `fetch` 调用 Supabase REST API，不引入 SDK 或构建工具。
- 提交中禁用按钮，成功后清空并自动关闭；失败时保留内容并显示错误。
- 深色/浅色主题、键盘 Esc、点击遮罩关闭、移动端布局和无障碍状态均保留或补齐。

V3 仍为静态网页，不引入 React、Tailwind、Node 或第三方运行时依赖。

## 2. Supabase 数据流

```text
反馈弹窗
  → fetch POST
  → Supabase REST API /rest/v1/feedback
  → Postgres public.feedback
  → 你在 Supabase Table Editor 查看
```

### 2.1 数据表

`public.feedback` 只有三类字段：

- `id`：自动递增主键；
- `message`：必填反馈内容，1–1000 字；
- `created_at`：自动创建时间。

### 2.2 安全策略

- 前端只使用 **anon public key** 或可公开的 publishable key。
- `service_role` / secret key 严禁进入前端或公开仓库。
- `public.feedback` 已开启 RLS。
- 匿名角色只允许 `INSERT`，不允许读取已有反馈。
- 实测匿名 POST 返回 HTTP 201，匿名 GET 返回 HTTP 401（permission denied），符合预期。
- 测试数据已从表中删除。

完整建表 SQL 见 `supabase_feedback.V3.sql`。
